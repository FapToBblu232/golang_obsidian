### Семинар 2
#### SQL (ANSI)
3 Группы:
1) **DCL** - Data Control Language. Управление разрешениями доступа. 
	1) `Grant` - разрешить
	2) `Deny` - запретить
	3) `Revoke` - отозвать разрешение или запрет
2) **DDL** - Data Definition Language
	1) `Create` - создать объект
	2) `Alter` - изменить объект
	3) `Drop` - удалить объект
3) **DML** - Data Manipulation Language. Для работы с данными.
	1) `Select` - выборка данных
	2) `Insert` - добавление
	3) `Update` - изменение данных
	4) `Delete` - удаление

**MS SQL** и **PostgreSQL** - работать будем с ними

			- Файл данных `*.mdf`, далее `*.ndf`. Из model копируется. Здесь грязные данные.

#### PostgreSQL

На сервере создаётся кластер.
Пользователи подключаются к кластерам:
- Старшие системные таблицы:
	- `Template0` - для восстановления
	- `Template1` - пользовательский шаблон. Шаблон для новых БД
	- `Postgres` - Сама PostgreSQL. В ней можно создавать свои таблицы. Бд для работы.
- Здесь же и лежат пользовательские БД (в кластере)
	- Схемы:
		- `pg_catalog` - здесь вся инфа для управления бд. (вся системная информация)
		- `pg_temp` - временные объекты
		- `public` - пользовательские таблицы

PGDATA (каталог):
- `BASE` (по id) Для каждого объекта минимум 1 файл. Тут наши данные.
	- 1\тут файлы объектов
	- 2
	- 5
- `GLOBAL` (Тут лежат файлы, общие для всех бд кластера)
	- `pg_database` - системная таблица с описанием всех пользовательских бд

Поэтому перекинуть просто файл - нельзя, т.к. сервер должен знать о БД.
Пользователи кластера имеют доступ ко всему кластеру. Поэтому принято, что для одного кластера - одна БД.

*Как создать?*
`Create database <name>;` 

`use <dataBase_name>` - начать использовать
Создаём объекты:
- Стандартные
	- Таблица `Table`
	- `Datatype` - пользовательские типы данных. Типы данных со своими ограничениями
	- `Constraint` - ограничения на ввод данных. **PK**, **FK**
	- `Index` - надстройка над таблицей типа предметного указателя
	- `View` - представления. Работаем с данными, чтобы пользователю было удобно. Может что-то вычисляем.
	- `Functions` - разовые маленькие операции
	- `Proedure` - программки побольше, которые работают с данными. Руками вызываем.
	- `Trigger` - процедура после определённого события. Автоматом запускаются.
- Остальные - нестандартные.
	- `Rule`
	- `Default`
В имени Объектов есть свои ограничения:
- Начинается с буквы
- Далее можно цифры, символы
- Без `@, $, %, #`
Экранирование при помощи `[ ]`. Иначе может подумать, что это команда.
В PostgreSQL - ещё и `" "`

**MSSQL**:
- <Имя сервера>.<Имя БД>.<Владелец>.<Имя объекта>
- Если владелец - пустой, то это DB owner
- `shop..products`
**PgSQL**:
- <кластер>.<Имя БД>.<Имя Схемы>.<Объект>
- `shop.public.products`
- `public.products` - Схема важна

#### Создание таблицы
```
Create table <имя> (
Имя столбца, тип данных, Null/NotNull - для MSSQL,
...,
...,
...
); - для PgSQL
```

```
Create table Products (
p_id int Not Null,
p_name char(20)
)
```
**Добавить столбец**
```
Alter table <name>
	Add __column__ (<имя столбца>...)
	Alter column (Имя столбца новый параметр)
	Drop column <имя столбца>
```
```
Alter table Products
Add (price decimal(7,2));

Alter table Products
Alter column(p_name varchar)
```
**Удалить таблицу**
```
Drop table <name>
```

**Генерация значений столбца**
1) PgSQL : serials - его можно менять
2) MSSQL Identity(нач_знач, приращение) - нельзя менять. Можно задать начальное значение и приращение
Generate Always as Identity

```
Create table Products
(p_id int serials,
...,
...);
```

```
Create table Products
(p_id int Identity(100,10) Not Null,
...,
...)
```
