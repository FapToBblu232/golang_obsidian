##### Ролевая - Role Based Access Control
Ситуация - много однотипных филиалов - хочется иметь предсозданные наборы доступов - роли

**Ролевое управление доступом**
- Ролевая модель управления доступом содержит ряд особенностей, которые не позволяют отнести её *ни к категории дискреционных, ни к категории мандатных моделей.*
- Основная идея: понятие «субъект» заменяется двумя новыми понятиями:
- *пользователь* - человек, работающий в системе;
- *роль* - активно действующая в системе абстрактная сущность, с которой связан ограниченный и логически непротиворечивый набор полномочий, необходимых для осуществления тех или иных действий в системе
- Основным достоинством ролевой модели является близость к реальной жизни

Формальное описание системы
- U - множество пользователей;
- R - множество ролей;
- Р - совокупность полномочий на доступ к объектам (реализованная,
например, в виде матрицы доступа);
- S - множество сеансов работы пользователей с системой
Управление доступом реализуется с использованием следующих отображений:
- `PА c PxR` - отображение множества полномочий на множество ролей,
задающее для каждой роли установленный набор полномочий;
- `UA c UxR` - отображение множества пользователей на множество ролей, определяющее набор ролей, доступных данному пользователю;

**Формальное описание системы**
- user: `S ->U` - функция, определяющая для сеанса `s E S` текущего пользователя `u E U`
user(s) = u;
- roles : `S -> {R}` - функция, определяющая для сеанса `s E S` набор ролей из множества R, доступных в данном сеансе:
roles(s)={r,| (user(s),r;) EUA};
- permissions : `S -> {P}` - функция, задающая для сеанса s E S набор доступных в нём полномочий (иначе говоря, совокупность полномочий всех ролей, доступных в данном сеансе):
permissions(s) = Y{p; | (p;,r) єPA}.
reroles(s)

Критерий безопасности системы
Система считается безопасной, если любой пользователь в системе, работающий в сеансе `s E S`, может осуществлять действия, требующие полномочий `p E P`, только в том случае, если `p E permissions(s)`

##### Атрибутное управление доступа Attribute Based Access Control
- Наиболее универсальная модель управления доступом
- Основная идея: решение о предоставлении доступа субъекта к объекту принимается на основе анализа набора произвольных атрибутов, связанных с субъектом, объектом или даже средой их функционирования.
- Каждый атрибут представляет собой некий набор данных, который может быть сопоставлен с массивом допустимых значений данного атрибута

**Формальное описание модели**
- S- множество субъектов;
- О - множество объектов;
- Е - множество элементов среды;
- `SA_k`, k = 1,K - множество возможных атрибутов *субъектов*;
- `ОА_m`, m = 1, M - множество возможных атрибутов *объектов*;
- `EА_n`, n = 1,N - множество возможных атрибутов элементов *среды*;
Для задания атрибутов конкретным субъектам, объектам или элементам среды используются следующие три отношения:
- `ATTR(s) c SA_1 x SA_2 x ... x SA_x`;
- `ATTR(o) c OA_1 x OA_2 x ... x OA_м`;
- `ATTR(e) c EA_1 x EA_2 x ... X EA_м`;
В общем случае правило политики безопасности, разрешающее или запрещающее доступ, представляет собой булеву функцию следующего вида:
**Rule_X**: `can_access(s,o,e) <- f(ATTR(s),ATTR(o), ATTR(e))`

##### Скрытые каналы передачи информации
Каналы связи изначально не относятся к безопасным
**Стеганография** - наука и способ скрытой передачи или хранения информации, при котором прячут не само содержимое сообщения (как в криптографии). 

- Неформально под скрытым каналом передачи информации понимают любой
канал связи, изначально для передачи информации не предназначенный.
- Для нас будут представлять интерес скрытые каналы, реализуемые за счёт
особенностей формальных моделей управления доступом
![[Pasted image 20261106110313.png|447]]
Пусть имеется модель мандатного управления доступом М и её реализация І(М). Тогда любая потенциальная связь между двумя субъектами I(sh) и I(s;) называется скрытым каналом передачи информации (рис. 2.7.1), если эта связь не разрешена в модели М

**Типы скрытых каналов**
- Скрытые каналы по памяти, в которых информация передаётся через доступ отправителя на запись и получателя на чтение к одним и тем же ресурсам или объектам; (читаем биты настроек, например биты доступа)
  ![[Pasted image 20261106110525.png|405]]
- Скрытые каналы по времени, которые характеризуются доступом отправителя и получателя к одному и тому же процессу или изменяемому во времени атрибуту. (сколько времени пользовался один субъект объектом - вектор)

###### Методы выявления скрытых каналов передачи информации
**Метод разделяемых ресурсов Кемерера**
- для каждого разделяемого ресурса в системе строится матрица, строки которой соответствуют всевозможным атрибутам разделяемого ресурса, а столбцы - операциям, выполняемым в системе;
- значения в ячейках матрицы соответствуют воздействиям, осуществляемым при выполнении тех или иных операций в отношении атрибутов разделяемых ресурсов.
- Получившаяся в результате матрица позволяет отследить информационные потоки, существующие в системе.
 **Сигнатурный анализ** исходных текстов программного обеспечения.
- данный метод предполагает проведение анализа исходных текстов программ с целью выявления конструкций, характерных для скрытых каналов передачи информации.
