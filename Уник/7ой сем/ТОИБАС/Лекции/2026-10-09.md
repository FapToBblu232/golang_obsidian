**Формализация понятия доступа**
- Формальные модели управления доступом

**Цель**
- Поиск закономерностей
- Доказательство свойств безопасности
// Как формально доказать важным дядям, что у нас безопасная система?

А - конечный алфавит - обычно бинарный
А* - множество слов конечной длины
L из А* - Язык, т.е. множество слов

**Аксиома 1**
Любая информация в автоматизированных системах может быть представлена в виде слова в некотором языке L

**Объектом** относительно языка L Называется произвольное конечное множество слов языка L.
Клавиатура - конечные состояния, тоже можно описать

Преобразованием информации информации называется отображение, заданное на множестве слов языка L
Преобразование может:
- *Храниться* - в это случае описание преобразования хранится в некотором объекте и ничем не отличается от других данных
- *Действовать* - взаимодействует с некоторыми ресурсами АС. 

- Ресурсы системы, выделенные для действия преобразования, принято называть *доменом*
- Преобразование, которому передано управление, называется *процессом*
- Объект, описывающий преобразование, которому выделен домен и передано управление, называется *субъектом*
- Субъект для реализации преобразования использует информацию, содержащуюся в объекте, то есть осуществляет *доступ* к объекту.

Виды доступа:
- *Чтение* - Если субъект S получает доступ к объекту О на чтение, то это означает, что производится перенос информации от объекта О к субъекту S - иначе говоря возникает информационный *поток от О к S*
- *Запись* - Если субъект S получает доступ к объекту О на запись, то это означает, что производится перенос информации от субъекта S к объекту O - иначе говоря возникает информационный *поток от S к O*

**Аксиома 2**
Все вопросы безопасности информации описываются доступами субъектов и объектам

#### Монитор безопасности обращений
- Монитор безопасности обращений (SRM - security reference monitor) представляет собой фильтр, который разрешает или запрещает доступ, основываясь на установленных в системе правилах разграничения доступа.
  Модуль, который был запрограммирован на ответ всего. Смотрит в Базу Правил

**Требования**:
- Ни один запрос на доступ субъекта к объекту не должен выполняться в обход МБО
- Работа МБО должна быть защищена от постороннего вмешательства
- Представление МБО должно быть достаточно простым для возможности верификации корректности его работы.

##### Модель Харрисона-Руззо-Ульмана
- Разработана в 1971г
- Формализует понятие **матрицы доступа** - таблицы, описывающей права доступа
S - множество возможных субъектов
O - множество возможных объектов
R = {r1...rn} - конечное множество прав доступа
OSR - пространство всех состояний системы
M - матрица прав доступа, описывающее текущие права доступа субъектов к объектам
Q=(S,O,M) - текущее состояние системы
M\[s,o\] - ячейка матрицы

**Команды**
Поведение системы во времени моделируется переходами между различными её состояниями
Переходы осуществляются путём внесения изменений в матрицу М с использованием команд следующего вида
```
command a(x1,..,x2)
	if r1 in M[xs1,xo1] and
	   r1 in M[xs2,xo2]
		.....
	then
	op1
	op2
	op3
	
end
```

op - Элементарные операции
1) enter r into M\[s,o\] - добавление субъекту права по отношению к субъекту
2) delete r from M\[s,o\] - удаление у субъекта права по отношению к объекту.
3) create subject s - создание нового субъекта
   Множество объектов меняется, так как **любой субъект - это объект, но не наоборот**.
   Ячейку заполняем пустотой.
4) destroy subject s
5) create object o
6) destroy object o

```
command create_file(p, f)
	create object f,
	enter own into M[p,f],
	enter r into M[p,f],
	enter w into M[p,f],
end
```

**Формальное описание**
- Система состоит из следующих элементов:
	- Конечный набор прав доступа R={r1...rn}
	- Конечный набор исходных субъектов
	- Конечный набор исходных объектов 
	- Исходная матрица доступа M0
	- Конечный набор команд
- Поведение системы во времени рассматривается как последовательность состояний {Qi}, каждое последующее состояние является результатом применения некоторой команды к 
- Для заданной системы начальное состояние называется безопасным относительно права r, если не существует применимой к Q0 последовательности команд, в результате выполнения которой право r будет занесено в ячейку матрицы, в которой оно отсутствовало в состоянии
- Если же право оказалось в ячейке матрицы, к которой оно изначально отсутствовало, то говорят, что произошла **утечка права r.**

Пример
3 субъекта, чтение и запись
3 команды 
```
command create(s,o)
	create subject o,
	enter r into M[s,o],
	enter w into M[s,o]
end
```

```
command takex(s,o,p)
	if r in M[s,o] and
	   x in M[o,p]
    then
		enter x into M[s,p]
end
```

```
command grantx(s,o,p)
	if w in M[s,o] and
	   x in M[s,p]
    then
		enter x into M[o,p]
end
```

Система называется *монооперационной*, если каждая команда выполняет только один примитивный оператор
