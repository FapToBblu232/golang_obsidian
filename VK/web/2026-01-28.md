### Лекция от 08.11
#### Реляционные базы данных
От английского `relation`. Все данные связаны между собой.
Самые популярные: `MySql` и `PostgreSQL`
Есть ещё:
- Колоночные
- Нереляционные (NoSQL) - примерами служат MongoDB (для работы с файлами. Обычно JSON)
- Векторные
##### Какие же проблемы они решают?
- Структура хранения 
- Эффективный поиск данных
- Управление памятью
- Совместный доступ к данным
- Атомарные операции - транзакции
- Язык управления базой и данными - **SQL** (**Structured Query Language**)

##### Общая информация
![[Pasted image 20260128225129.png]]
- Колонки в реляционной алгебре называются Полями.
  Эти самые колонки могут хранить данные только **одного типа**.
- Название обычно называется как <название приложения>\_<название бд>
- Связи бывают "**один ко многим**", "**один к одному**" (foreign key), "**многие ко многим**"

##### Проектирование БД
Зачем нам вообще это надо?
- Сокращать избыточность и дублирование данных.
- Выделение сущностей.
- **Нормальные формы** базы данных - формальные правила проверки схемы базы данных на "правильность".
	- Данные не дублируются между табличками

Что делаем?
- Логическое разделение сущностей
- Выделение синтетических первичных ключей
- Связи 1:N, N:1 реализуются через внешний ключ
- Связи 1:1 реализуются через внешний ключ с unique index
- Связи N:М реализуются через промежуточную таблицу
- Атрибут с фиксированным числом значений - внешняя таблица либо поле типа enum

#### QuerySet

**QuerySet** - объекты, представляющие собой запрос к базе данных. Именно **запрос**, а не его результаты. QuerySet являются **ленивыми (lazy)** объектами. Это значит, что запрос осуществляется не в момент создания QuerySet, а **в момент итерации по нему**, либо **вызова метода, возвращающего результат**.
![[Pasted image 20260203155726.png]]
Т.е. вызов будет только один в самом конце

##### Что можем chain'ить?
- `filter` , `exclude` - фильтрация, в SQL это WHERE
- `order_by` - сортировка
- `annotate` - выборка агрегатов, в SQL это JOIN и GROUP BY
- `values` - выборка отдельных колонок, а не объектов
- `distinct` - выборка уникальных значений
- `select_related`, `prefetch_related` - выборка из нескольких таблиц
![[Pasted image 20260203160141.png]]
второй вариант - проведёт ещё один запрос, но затратит меньше памяти

##### Чем завершаем?
- `create` - создание нового объекта
- `update` - обновление всех подходящих объектов
- `delete` - удаление всех подходящих объектов
- `count` - выборка количества `COUNT(*)`
- `get_or_create` - выборка объекта или его создание
- `update_or_create` - обновление объекта или его создание

Название полей не может содержать `__`, т.к.
- `field = value` - точное совпадение
- `field__contains` = value - суффикс оператора LIKE
- `field__isnull`, `field__gt`, `field__lte`
- `relation__field = value` - условие по связанной таблице
- `сategory__ title__contains = "Perl"` - долго

##### Миграции
**Миграция** - это процедура изменения схемы базы данных для приведения её в соответствие с моделями.

#### Best Practices
#####  Fat Controller
Слишком жирные вьюхи)

Типичная проблема начинающих разработчиков - размещение логики в контроллерах. Это плохое решение, у которого есть имя - антипаттерн Fat Controller. 
Размещение логики в контроллере лишает вас возможности использовать ее повторно. **Всю бизнес-логику приложения следует размещать в моделях или в отдельном модуле services.py.**
