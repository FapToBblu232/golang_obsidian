`slug` имеет меньшее кол-во разрешённых символов + иногда его нужно генерить самому. Это нужно, чтобы не по id искать, а, например, по нику.

#### Обработка форм
Нужны для получения и редактирования информации.
Обычно **Get** используется для поиска чего-то, а **Post** для всего остального.
**Get** - могут быть закешированы промежуточными серверами.
**Post** - не кешируются.

##### Best Practices
- Всегда проверять пользовательские данные
- Для форм, изменяющих данные, использовать метод POST
- Не заставлять вводить данные повторно
- Сообщать об ошибках детально - по полям
- Сообщать об успешном сохранении формы, чтобы пользователь мог понять, что его данных ушли, а не просто формочка отчистилась.
- При успешном сохранении делать перенаправление

##### Перенаправление
- `302 Found` - временное перенаправление
- `301 Moved Permanently` - постоянное перенаправление (кешируется в браузере)
- `Location: ur1` - URL для повторного запроса. Может быть как абсолютным, так и относительным.
![[Pasted image 20260205151328.png]]
В коде это выглядит, как просто `return HttpResponseRedirect("/new_url/")`
Иногда в url запросах есть такой параметр **continue**, вот такое передавать сразу в редирект - опасно. (уязвимость Open Redirect)

##### Валидация данных
- По типу поля, например `EmailField`
- `clean_xxx` - доп. проверка поля ххх, может изменить значения
- `clean` - доп. проверка всех полей формы
- Методы `clean` и `clean_xxx` должны использовать `self.cleaned_data` для получения данных формы и поднять `ValidationError` в случае некорректных данных.

##### CSRF
**Cross Site Request Forgery** (forgery = подделка)
![[Pasted image 20260205160711.png]]
Смысл в том, что мы можем юзать куку с другой сессии, это позволит нам прийти к серверу, который скажет: "А, о, такая сессия есть, авторизуем!"

**Что делаем?**
- `@reqired_POST`
- Проверка заголовка `Referer`
- Проверка **CSRF** токена
![[Pasted image 20260205161150.png]]
Что это такое и зачем это надо?
Ситуация:
- Приходит юзер, просит `GET/login`
- Ему отдаётся http/1.1 200ok + set Cookie csrftoken=eflkkfdslfdlkjs
- Далее юзер отдаёт POST/login + параметры login=hihihi&pass=hahaha&csrftoken=eflkkfdslfdlkjs
- Сервер отдаёт 200
Весь смысл заключается именно в том, что мы проверим эти параметры, если в них есть наш токен, то мы его проверим. Если сайт уязвимый, то куку он не прочитает и параметра этого не будет.

##### Cookie
**Cookies** - небольшие фрагменты данных, которые браузер хранит **на стороне клиента** и передает на сервер при каждом запросе. Cookies привязаны к доменам, поэтому при каждом запросе сервер получает только «свои» cookies. Невозможно получить доступ к cookies с другого домена. Cookies используются для поддержания состояния (state management) в протоколе HTТР и, в частности, для авторизации.

У кук есть следующие атрибуты:
- `name=value` - имя и значение cookie
- `Expires` - время жизни cookie, по умолчанию - до закрытия окна.
- `Domain` - домен соокіе, по умолчанию - домен текущего URL.
- `Path` - путь cookie, по умолчанию - путь текущего URL.
- `Secure` - cookie должна передаваться только по https
- `Http0nly` - cookie не доступна из JavaScript

Как удалить куку? - Поставить атрибут `Expires` в прошлое.
